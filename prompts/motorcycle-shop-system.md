# ข้อกำหนดระบบ: ระบบจัดการธุรกิจร้านกมลกิจยานยนต์

ระบบบริหารจัดการธุรกิจสำหรับร้านขายและซ่อมรถจักรยานยนต์ ครอบคลุม 5 สายงานหลัก:
- จำหน่ายรถจักรยานยนต์มือหนึ่งและมือสอง
- รับซ่อมบำรุงรถจักรยานยนต์ทุกยี่ห้อ
- จำหน่ายอะไหล่รถจักรยานยนต์
- ให้บริการสินเชื่อผ่อนชำระรถจักรยานยนต์ (In-house Financing)
- ให้บริการทำ พ.ร.บ. และต่อภาษีรถประจำปี

---

## 1. การจัดการข้อมูลหลัก (Master Data)

### 1.1 รถจักรยานยนต์
- ขายทั้ง **รถใหม่** และ **รถมือสอง**
- รถมือสอง: มีการ **รับซื้อเข้า (trade-in)** ต้องบันทึกทั้ง **ราคารับซื้อ** และ **ราคาขายออก** เพื่อคำนวณกำไร
- บันทึก **ประเมินสภาพรถรับซื้อ**: สภาพทั่วไป ไมล์ รายการซ่อมที่พบ หมายเหตุ
- ข้อมูลรถ: ยี่ห้อ รุ่น สี ปี หมายเลขเครื่อง หมายเลขตัวถัง ทะเบียน สถานะ (ในสต็อก/ขายแล้ว/จอง/ยึดคืน)
- บันทึก **ระยะเวลาประกัน (warranty)** สำหรับรถใหม่ที่ขาย
- เลขตัวถังและเลขเครื่องต้องไม่ซ้ำกัน (unique) ในระบบ

### 1.2 ลูกค้า
- ข้อมูลส่วนตัว: เลขบัตรประชาชน (13 หลัก พร้อม checksum), ชื่อ-นามสกุล, ที่อยู่ (ตำบล/อำเภอ/จังหวัด/รหัสไปรษณีย์), เบอร์โทร, เบอร์โทรสำรอง, LINE ID
- ลูกค้าสามารถ **ค้างชำระบริการ พ.ร.บ./ต่อทะเบียน/ตรวจสภาพรถ ต.ร.อ.** ได้ โดยค่อยจ่ายตอนมารับเล่มทะเบียนกลับ — **ค่างวดรถและค่าซ่อมต้องชำระทันที ค้างไม่ได้**
- ประวัติการซื้อ การซ่อม การชำระเงินทั้งหมด
- จัดกลุ่มลูกค้า: ลูกค้าประจำ, ลูกค้าค้างชำระสูง, ลูกค้าผ่อนครบแล้ว
- เลขบัตรประชาชนและเบอร์โทรต้อง mask ใน Log ตาม **พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 มาตรา 37**
- รองรับการ Merge ลูกค้าที่ซ้ำกัน (Admin เท่านั้น)

### 1.3 ซัพพลายเออร์อะไหล่ (Suppliers)
- บันทึกข้อมูลซัพพลายเออร์: ชื่อ เบอร์โทร เงื่อนไขการสั่งซื้อ
- เชื่อมกับระบบสั่งซื้ออะไหล่ (Purchase Order)

### 1.4 ผู้ค้ำประกัน (Guarantor)
- สัญญาผ่อนชำระสามารถมีผู้ค้ำประกันได้ (ไม่บังคับ)
- ข้อมูล: ชื่อ-นามสกุล, เลขบัตรประชาชน, เบอร์โทร, ที่อยู่, ความสัมพันธ์กับลูกค้า
- ผู้ค้ำประกัน 1 คนสามารถค้ำได้หลายสัญญา
- **พนง.ติดตามหนี้**: ดูข้อมูลผู้ค้ำประกันได้เมื่อออกติดตามหนี้ แต่แก้ไขไม่ได้
- **เสมียน/Admin**: แก้ไขข้อมูลได้

## 2. ระบบซื้อ-ขายรถ และสัญญาเช่าซื้อ (Hire-Purchase)

### 2.1 สัญญาซื้อขาย
- สัญญาซื้อขายเงินสด
- สัญญาเช่าซื้อ (ผ่อนชำระ)

**รูปแบบเลขที่สัญญา:** `{01|02}-{ปี พ.ศ. 2 หลัก}-{running number 3 หลัก}`
- `01` = รถใหม่, `02` = รถมือสอง
- ตัวอย่าง: `01-69-042`
- ระบบสร้างเลขที่สัญญาอัตโนมัติ ไม่ซ้ำกัน

**การจองรถ:**
- รถสามารถ "จอง" ได้ (status = `reserved`) โดยเสมียน
- รถที่จองแล้วจะไม่แสดงในรายการรถพร้อมขาย
- มีระยะเวลากำหนด ถ้าไม่มาทำสัญญาภายในระยะเวลาที่กำหนด ระบบเปลี่ยนสถานะกลับเป็น `in_stock` อัตโนมัติ

**รับซื้อรถแลก (Trade-in):**
- รองรับกรณีลูกค้านำรถเก่ามาแลกเป็นส่วนลด
- รถที่รับมาบันทึกเข้าสต็อกเป็นรถมือสอง พร้อมมูลค่าที่ตีราคา
- มูลค่า trade-in หักจากราคาขายก่อนคำนวณยอดผ่อน (ถ้าผ่อน)

### 2.2 ระบบผ่อนชำระ — ต้องเป็นไปตามกฎหมายไทย
ระบบต้องรองรับการคำนวณและบันทึกตามหลักเกณฑ์ดังนี้:

**การคำนวณ:**
- ใช้ระบบ **Flat Rate** (มาตรฐานอุตสาหกรรมเช่าซื้อไทย)
- สูตร: ดอกเบี้ยรวม = เงินต้นคงค้าง × Flat Rate × จำนวนปี
- ค่างวด = (เงินต้น + ดอกเบี้ยรวม) / จำนวนงวด
- ต้องคำนวณและแสดง **Effective Rate (อัตราดอกเบี้ยที่แท้จริงต่อปี)** ด้วย เพราะกฎหมายกำหนด
- ระยะเวลาผ่อน: 12–48 งวด
- วันผ่อนผัน (grace period): กำหนดได้ต่อสัญญา ค่า default 7 วัน
  - ตัวอย่าง: ครบกำหนดวันที่ 15 + grace period 7 วัน → เริ่มคิดค่าปรับตั้งแต่วันที่ 23

**ข้อกำหนดทางกฎหมาย:**
> **ประกาศคณะกรรมการว่าด้วยสัญญา** เรื่อง ให้ธุรกิจให้เช่าซื้อรถยนต์และรถจักรยานยนต์เป็นธุรกิจที่ควบคุมสัญญา **พ.ศ. 2565**
> ประกาศราชกิจจานุเบกษา 12 ตุลาคม 2565 — **มีผลบังคับใช้: 10 มกราคม 2566**
> บังคับใช้กับทั้งสถาบันการเงินและผู้ประกอบการที่ไม่ใช่สถาบันการเงิน (รวมถึงร้านขายรถ)

| ประเภทรถ | Effective Rate สูงสุด |
|---|---|
| รถยนต์ใหม่ | 10% ต่อปี |
| รถยนต์มือสอง | 15% ต่อปี |
| **รถจักรยานยนต์ (ใหม่และมือสอง)** | **23% ต่อปี** |

- **เบี้ยปรับล่าช้า: ไม่เกิน 5% ต่อปี** ของจำนวนเงินที่ผิดนัดชำระ (คำนวณเฉพาะค่างวดที่ค้าง ห้ามนำหนี้ที่ยังไม่ถึงกำหนดมาคิด)
- สัญญาต้องระบุ: ราคาเงินสด, เงินดาวน์, ค่างวด, จำนวนงวด, Effective Rate, ดอกเบี้ยรวม, ยอดรวมทั้งหมด, อัตราเบี้ยปรับ, เงื่อนไขบอกเลิกสัญญา, สิทธิชำระก่อนกำหนด
- บังคับใช้กับทั้งสถาบันการเงินและผู้ประกอบการที่ไม่ใช่สถาบันการเงิน (รวมถึงร้านขายรถ)

**ช่องทางชำระเงิน:** เงินสด, โอนธนาคาร, PromptPay — ทุกช่องทางบันทึกเป็น Cash Transaction เหมือนกัน

**การชำระบางส่วน (Partial Payment):**
- รองรับการจ่ายไม่ครบยอดงวด
- **ลำดับการจัดสรรเงิน**: ค่าปรับก่อน → ค่างวด → ค่าประกันรถหาย
- ยอดคงค้างต้องแสดงให้เสมียนและลูกค้าเห็น

**ชำระหลายงวดพร้อมกัน:** เลือกชำระหลายงวดในคราวเดียว ออกใบเสร็จรวม 1 ใบ

**ชำระล่วงหน้า:** จ่ายก่อนวันครบกำหนด ไม่มีค่าปรับ

**จ่ายปิดยอด (Early Payoff):**
- ยอด = ผลรวมค่างวดที่เหลือทั้งหมด + ค่าปรับค้าง + ค่าประกันรถหายค้าง
- ไม่มีส่วนลดอัตโนมัติ แต่ Admin สามารถอนุมัติส่วนลดได้ (ต้องบันทึกเหตุผล)

**สถานะสัญญา:**
- `active` — กำลังผ่อนอยู่
- `completed` — ผ่อนครบทุกงวดแล้ว
- `defaulted` — ผิดนัด/ยึดรถ (Admin เปลี่ยนเท่านั้น ต้องบันทึกเหตุผล)
- `closed_theft` — ปิดเนื่องจากรถถูกขโมย (Admin อนุมัติ + มีหลักฐานใบแจ้งความ)

### 2.3 การตัดสดก่อนกำหนด (Early Settlement)
ระบบต้องคำนวณยอดตัดสดตามกฎหมายได้ทันที (ห้ามเรียกเก็บค่าธรรมเนียมปิดบัญชีก่อนกำหนด):

| งวดที่ชำระแล้ว | ส่วนลดดอกเบี้ยขั้นต่ำ |
|---|---|
| ≤ 1/3 ของสัญญา | ลดอย่างน้อย **60%** ของดอกเบี้ยที่เหลือ |
| > 1/3 แต่ ≤ 2/3 | ลดอย่างน้อย **70%** ของดอกเบี้ยที่เหลือ |
| > 2/3 ขึ้นไป | **ยกดอกเบี้ยที่เหลือ 100%** |

**สูตรคำนวณยอดตัดสด:**
```
ยอดตัดสด = เงินต้นคงเหลือ + (ดอกเบี้ยคงเหลือ × (1 - อัตราส่วนลด))
```

ตัวอย่าง: ผ่อนมาแล้ว 8/24 งวด (≤ 1/3), เงินต้นคงเหลือ 100,000, ดอกเบี้ยคงเหลือ 16,800
→ ยอดตัดสด = 100,000 + (16,800 × 40%) = **106,720 บาท** (ประหยัดดอกเบี้ย 10,080 บาท)

### 2.4 กระบวนการยึดรถคืน (Repossession)
ระบบต้องบันทึกขั้นตอนตามกฎหมาย:
1. **ผิดนัดชำระ** — บันทึกงวดที่ค้าง
2. **หนังสือแจ้งเตือน** — ต้องให้เวลาอย่างน้อย 30 วัน (**ป.พ.พ. มาตรา 574**)
3. **บอกเลิกสัญญา** — ได้เมื่อผิดนัดติดต่อกัน **2 งวดขึ้นไป** (**ป.พ.พ. มาตรา 574**)
4. **ยึดรถคืน** — ต้องได้รับความยินยอมหรือคำสั่งศาล ห้ามยึดโดยพลการ
5. **ปิดบัญชี** — เมื่อยึดรถแล้ว ค่างวดที่ชำระไปตกเป็นของผู้ให้เช่าซื้อ แต่ไม่มีสิทธิเรียกค่างวดที่เหลือ

> **กฎหมายอ้างอิง:** ประมวลกฎหมายแพ่งและพาณิชย์ (ป.พ.พ.)
> - **มาตรา 572**: นิยามสัญญาเช่าซื้อ
> - **มาตรา 573**: สิทธิบอกเลิกสัญญาโดยผู้ให้เช่าซื้อ
> - **มาตรา 574**: สิทธิบอกเลิกสัญญาเมื่อผิดนัดชำระ 2 งวดติดต่อกัน

### 2.5 เล่มทะเบียนรถ (Title / Registration Tracking)
- ลูกค้าที่ **ผ่อนอยู่**: เล่มทะเบียนอยู่ที่ร้าน
- ลูกค้าทั่วไป: เอาเล่มทะเบียนมาให้ หรือเป็นสำเนาก็ได้
- ต้องติดตาม **สถานะเล่มทะเบียนทุกเล่ม**: อยู่ที่ร้าน / อยู่กับลูกค้า / ส่งต่อภาษี / สูญหาย
- เมื่อลูกค้าชำระครบ: workflow ส่งคืนเล่มทะเบียน พร้อมบันทึกวันที่คืน
- บันทึก **วันหมดอายุ พ.ร.บ. / ภาษี** ของรถทุกคันที่ร้านดูแลเล่มทะเบียน

### 2.6 ประกันรถหาย (Theft Insurance Fund)
ร้านบริหารกองกลางประกันรถหายเอง (ไม่ใช่บริษัทประกัน):

- **บังคับ** สำหรับรถใหม่ที่ขายแบบผ่อนชำระ
- **ไม่บังคับ** (แต่เลือกซื้อได้) สำหรับรถมือสองที่ผ่อนชำระ
- ไม่ใช้กับการขายเงินสด
- ค่าเบี้ยประกันต่องวด: กำหนดได้ต่อสัญญา (เช่น 50–100 บาท/งวด)
- เก็บพร้อมกับค่างวด **แสดงแยกบรรทัด** ทั้งบนหน้าจอและในใบเสร็จ
- ค่าเบี้ยประกันไม่นำมาคำนวณค่าปรับล่าช้า

**กรณีรถถูกขโมย:**
- ต้องมีใบแจ้งความเป็นหลักฐาน
- **Admin เป็นผู้อนุมัติ** — บันทึก: วันที่รถหาย, เลขที่ใบแจ้งความ, วันที่อนุมัติ, ผู้อนุมัติ
- งวดที่เหลือทั้งหมดถูกยกเลิก, สัญญาเปลี่ยนเป็น `closed_theft`
- ลูกค้าไม่ต้องรับผิดชอบยอดคงค้าง, ร้านรับความเสียหายจากกองกลาง

**กองกลาง:**
- ยอดกองกลาง = ค่าเบี้ยที่เก็บได้รวม − ความเสียหายจากรถหายรวม
- Admin ยกเว้นการบังคับซื้อประกันได้เป็นกรณีๆ (ต้องบันทึกเหตุผล + ผู้อนุมัติ)
- รายงานกองกลาง: ยอดปัจจุบัน, รายการเงินเข้าแยกตามสัญญา, รายการเงินออกแยกตามเคส, จำนวนเคส, อัตราเคลม

**การคืนเบี้ยประกัน:** ไม่คืน (non-refundable) เมื่อผ่อนครบ

**ความคุ้มครอง:** เฉพาะกรณี "ถูกขโมย" เท่านั้น ไม่รวมอุบัติเหตุ, ไฟไหม้, น้ำท่วม, สูญหายจากความประมาท

### 2.7 ถ่ายรูปลูกค้า (Customer Photos)
> **กฎหมาย:** พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 **มาตรา 24, 26** — ต้องขอ Explicit Consent ก่อนถ่ายรูปทุกครั้ง

- **บังคับ** สำหรับสัญญาผ่อนชำระ: รูปหน้าตรงลูกค้า + รูปลูกค้ากับรถ (อย่างน้อย 2 รูป จึงจะบันทึกสัญญาได้)
- **แนะนำแต่ไม่บังคับ** สำหรับขายเงินสด
- รูปเพิ่มเติม (optional): รูปบัตรประชาชน, รูปผู้ค้ำประกัน, รูปบ้านลูกค้า

**การจัดการรูป:**
- รูปทั้งหมดเชื่อมกับ contract_id พร้อมระบุประเภทรูป (photo_type): customer_face, customer_with_vehicle, id_card, guarantor, other
- บันทึกวันเวลาที่ถ่าย + บันทึกว่าลูกค้าให้ความยินยอมแล้ว (consent log)
- จัดเก็บใน File Storage แบบ **private** (ไม่สามารถเข้าถึงได้จาก public URL) มี backup
- รองรับไฟล์ JPEG, PNG ขนาดสูงสุด 10 MB ต่อรูป

**สิทธิ์เข้าถึงรูป:**
| Role | สิทธิ์ |
|---|---|
| เสมียน | อัปโหลด + ดูได้ตอนสร้างสัญญา |
| พนง.ติดตามหนี้ | ดูได้อย่างเดียว ดาวน์โหลดไม่ได้ |
| เจ้าของ/Admin | ดูได้ทุกอย่าง |
| ช่าง | ไม่มีสิทธิ์ |

- ลบรูปไม่ได้จนกว่าสัญญาจะ `completed` หรือ `defaulted`

## 3. ระบบทวงหนี้และติดตามหนี้ (Debt Collection)

### 3.1 รายชื่อลูกหนี้
- แสดงรายชื่อลูกค้าค้างชำระพร้อม Aging (จำนวนงวดที่ค้าง, จำนวนวัน, ยอดเงินค้าง)
- ต้องปฏิบัติตาม **พ.ร.บ.การทวงถามหนี้ พ.ศ. 2558**:
  - **มาตรา 9** — ทวงได้เฉพาะ วันจันทร์-ศุกร์ **08:00-20:00 น.**, วันหยุดราชการ **08:00-18:00 น.**
  - ทวงได้ **ไม่เกิน 1 ครั้งต่อวัน** ต่อลูกหนี้
  - **มาตรา 11, 14** — ห้ามใช้ถ้อยคำข่มขู่ ดูหมิ่น, ห้ามทวงกับบุคคลอื่นที่ไม่ใช่ลูกหนี้/ผู้ค้ำประกัน (ยกเว้นสอบถามที่อยู่), ห้ามทำให้ผู้อื่นรู้ว่าลูกหนี้มีหนี้
  - บทลงโทษ: ปรับสูงสุด 100,000 บาท และ/หรือจำคุกไม่เกิน 1 ปี

### 3.2 ช่องทางและประวัติการทวง
- ช่องทาง: **โทรศัพท์ / LINE / จดหมาย**
- ต้อง **บันทึกประวัติการทวงทุกครั้ง**: วันที่, ช่องทาง, ผลการทวง, หมายเหตุ
- รายงานลูกค้าค้างชำระและประวัติการทวงหนี้

### 3.3 มอบหมายงานและ Collector Module
**การมอบหมายงาน:**
- เสมียน/Admin เลือกลูกหนี้จากรายชื่อ มอบหมายให้ **พนง.ติดตามหนี้ (Collector)**
- ระดับความสำคัญ (priority): 0 = ปกติ, 1 = ด่วน, 2 = ด่วนมาก
- ข้อมูลที่ส่งให้ Collector: ลูกค้า (ชื่อ/ที่อยู่/เบอร์), สัญญา, ยอดค้าง, รูปลูกค้า, ข้อมูลผู้ค้ำประกัน (ถ้ามี)
- 1 สัญญามีงานติดตามที่เปิดอยู่ได้แค่ 1 งานในเวลาเดียวกัน

**Mobile App สำหรับ Collector:**
- ดูรายการงานที่ได้รับมอบหมาย เรียงตาม priority
- กดโทรหาลูกค้าได้ 1 แตะ
- เปิด Google Maps นำทางไปบ้านลูกค้าได้ 1 แตะ
- ดูรูปลูกค้า (อ่านอย่างเดียว ดาวน์โหลดไม่ได้)
- ดูข้อมูลผู้ค้ำประกัน (อ่านอย่างเดียว)

**บันทึกผลการติดตาม (7 ประเภท):**
1. `contacted_promise_to_pay` — ติดต่อได้ นัดจ่าย (ต้องระบุวันนัด)
2. `contacted_cannot_pay` — ติดต่อได้ แต่จ่ายไม่ได้
3. `not_home` — ไม่อยู่บ้าน
4. `unreachable` — ติดต่อไม่ได้
5. `paid_on_site` — จ่ายเงินครบหน้างาน
6. `partial_paid_on_site` — จ่ายบางส่วนหน้างาน
7. `other` — อื่นๆ (ต้องระบุหมายเหตุ)

**GPS Logging:**
> **PDPA:** ต้องแจ้ง Collector ก่อนว่า GPS จะถูกบันทึกขณะปฏิบัติงาน ตาม **พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 มาตรา 24**
- ระบบบันทึกตำแหน่ง GPS อัตโนมัติเมื่อ Collector บันทึกผลการติดตาม (เป็นหลักฐานการออกพื้นที่)
- ไม่ log GPS นอกเวลางาน

**รับเงินหน้างาน (Field Payment):**
- Collector รับเงินสดจากลูกค้าหน้างาน ระบุยอดเงินที่เก็บ
- ออก **ใบเสร็จชั่วคราว (Field Receipt)** เป็น PDF ให้ลูกค้าทันที
- เลขที่ใบเสร็จชั่วคราวแยกจากใบเสร็จร้าน (field_receipt_number)
- สถานะเงิน: `collected` (เก็บเงินแล้ว ยังไม่ส่งร้าน)

**ส่งมอบเงิน:**
- Collector กลับร้าน → ส่งเงินให้เสมียน → เสมียนตรวจรับและยืนยันยอด
- สถานะ: `collected` → `submitted` → `verified`
- เมื่อ `verified`: ระบบบันทึก Cash Transaction + อัปเดตงวดที่จ่าย (เหมือนรับเงินที่ร้าน)

**Offline Support:**
- Collector อาจอยู่ในพื้นที่ไม่มี Internet
- ระบบต้องรองรับบันทึกข้อมูลลง Local Storage ก่อน → Sync เมื่อมี Internet (Offline-first)
- ข้อมูลที่ต้อง cache: รายชื่อลูกหนี้, ประวัติลูกค้า, รูปลูกค้า

**Push Notification สำหรับ Collector:**
- แจ้งเมื่อได้รับงานใหม่
- แจ้งเมื่อลูกค้ามาจ่ายที่ร้านแล้ว (ไม่ต้องออกตาม)
- แจ้งเมื่องานถูกเปลี่ยนแปลง

**สรุปประจำวัน Collector:** จำนวนงานที่ทำ, เงินที่เก็บได้, ยอดที่ยังไม่ส่งร้าน

**รายงานการติดตาม:** สรุปผลลัพธ์ (จ่าย/นัดจ่าย/ติดต่อไม่ได้), เงินที่เก็บได้แยกตาม Collector

## 4. ระบบอะไหล่และสต็อก (Parts & Inventory)

- สแกน **barcode ที่ติดมากับสินค้า** (ไม่ต้องพิมพ์ barcode เอง)
- บันทึกอะไหล่เข้า-ออก พร้อม **ราคาต้นทุน** และ **ราคาขาย** เพื่อคำนวณกำไร
- ตั้ง **minimum stock (จุดสั่งซื้อ)** ระบบ **เตือนอัตโนมัติ** เมื่อสต็อกใกล้หมด
- **ขายปลีกอะไหล่แยกได้** (ไม่จำเป็นต้องเป็นงานซ่อม)
- เชื่อมกับระบบซ่อม: เมื่อใช้อะไหล่ในงานซ่อม ตัดสต็อกอัตโนมัติ
- บันทึก **ใบสั่งซื้อ (Purchase Order)** จากซัพพลายเออร์ และรับสินค้าเพิ่มสต็อก
- บันทึกประวัติการเคลื่อนไหว (stock movement) ทุกรายการ: วันที่, ประเภท (in/out/adjustment), จำนวน, ที่มา, ผู้ดำเนินการ

**ปรับสต็อกด้วยมือ (Stock Adjustment):**
- ปรับจำนวนเมื่อนับจริงไม่ตรงกับระบบ
- ต้องระบุเหตุผลและผู้ดำเนินการ
- บันทึกเป็น stock_movement ประเภท `adjustment`

**ตรวจนับสต็อก (Stock Audit):**
- รองรับการตรวจนับสต็อก (physical count) เป็นระยะ
- ระบบเปรียบเทียบยอดนับจริง vs ยอดในระบบ แสดงส่วนต่าง
- แก้ไขผ่าน Stock Adjustment หลังตรวจนับ

## 5. ระบบงานซ่อม (Repair/Service)

### Workflow งานซ่อม:
1. **เปิดใบรับรถ** — บันทึกทะเบียนรถ, ลูกค้า (optional สำหรับ walk-in), อาการเสีย
2. **ใบประเมินราคาซ่อม** — ประเมินค่าแรง + อะไหล่ก่อนลงมือซ่อม ให้ลูกค้าอนุมัติ (ป้องกันข้อพิพาท)
3. **ลงมือซ่อม** — บันทึก ช่างผู้ซ่อม, รายการอะไหล่ที่ใช้จริง, ค่าแรงจริง
4. **ปิดงาน** — สรุปค่าซ่อมรวม
5. **ออกใบเสร็จ** — ลูกค้าจ่ายเงินหรือค้างชำระได้

**ลูกค้า walk-in:**
- customer_id เป็น optional สำหรับงานซ่อม — ต้องมีเฉพาะทะเบียนรถ
- ลูกค้าที่ไม่มีในระบบสามารถเข้าซ่อมได้โดยตรง

**รายละเอียดอื่นๆ:**
- บันทึกงานซ่อม **warranty** แยกจากงานซ่อมปกติ
- ลูกค้าสามารถค้างชำระค่าซ่อมได้
- **จ่ายค่าแรงช่างผ่านระบบนี้ด้วย**
- รองรับ **การนัดหมายซ่อมล่วงหน้า** (วันที่ เวลา ช่างที่รับงาน)
- ช่างดูและจัดการได้เฉพาะงานที่ตัวเองรับผิดชอบ

**แนบรูปงานซ่อม (optional):**
- รองรับการแนบรูปถ่ายก่อน/หลังซ่อม
- เก็บใน File Storage

## 6. งานบริการ พ.ร.บ. / ต่อภาษี

- ลูกค้าสามารถ **ค้างชำระได้** หรือจ่ายเงินสดเลยก็ได้
- ลูกค้าผ่อน: เล่มทะเบียนอยู่ที่ร้าน (ดูแลต่อภาษีให้ได้)
- ลูกค้าทั่วไป: เอาเล่มทะเบียนหรือสำเนามาให้
- บันทึกวันที่ทำ พ.ร.บ. / ต่อภาษี และสถานะการชำระเงิน
- บันทึกประเภทเอกสารที่รับ: ตัวจริง (original) หรือ สำเนา (copy)
- ค่าธรรมเนียม (fee_amount) = ค่าที่ต้องจ่ายให้หน่วยงานรัฐ
- ค่าบริการ (service_charge) = ค่าที่ร้านเก็บจากลูกค้า
- ระบบ **แจ้งเตือนอัตโนมัติ** เมื่อ พ.ร.บ./ภาษีของรถที่ร้านดูแลใกล้หมดอายุ (แจ้งล่วงหน้า 30 วัน)

## 7. ระบบบัญชีประจำวัน (Daily Cash Management)

### 7.1 เงินส่วนกลาง (Petty Cash / Float)
- ทุกเช้า: จัดเงินส่วนกลางจำนวนเท่ากันทุกวัน ไว้ที่โต๊ะเสมียน (เพื่อทอนเงิน)
- ระบบต้องบันทึก **ยอดเปิดวัน (Opening Balance)**
- ต้องเปิดรอบเงินสดก่อนจึงจะบันทึกธุรกรรมได้

### 7.2 รายการเงินเข้า-ออก
- **เงินเข้า**: ค่างวดรถ, ค่าซ่อม, ค่าอะไหล่, ค่าบริการ พ.ร.บ., ค่าขายรถเงินสด, ค่าเบี้ยประกันรถหาย
- **เงินออก**: ช่างเบิกเงินซื้อของ, ค่าใช้จ่ายทั่วไป, ค่าแรงช่าง
- ต้อง **แยกประเภทค่าใช้จ่าย** (ค่าน้ำ/ค่าไฟ, ค่าอะไหล่, ค่าจ้าง, อื่นๆ)
- ต้อง **แยกรายได้ตามประเภท**: ขายรถ / ค่าซ่อม / ค่าอะไหล่ / ค่าบริการ พ.ร.บ. / ค่าเบี้ยประกันรถหาย
- Cash Transaction ที่บันทึกแล้วจะลบหรือแก้ไขไม่ได้ — ต้องใช้ reversal entry เท่านั้น
- ทุกรายรับจาก Module อื่น (ค่างวด, งานซ่อม, อะไหล่, พ.ร.บ., ขายรถ) ระบบสร้าง Cash Transaction อัตโนมัติ ไม่ต้องบันทึกซ้ำ

### 7.3 สรุปและตรวจนับเงินสิ้นวัน
- ตอนเย็น: สรุปยอดเงินเข้า-ออก ยอดคงเหลือ แยกตามประเภทรายได้
- **ตรวจนับเงินสดจริง** เทียบกับยอดในระบบ บันทึก **ส่วนต่าง (discrepancy)** หากเงินขาด/เกิน
- **เจ้าของร้านดูรายงานสรุปรายได้ประจำวัน** (ไม่ได้ลงข้อมูลเอง)

## 8. ระบบรายงาน (Reports)

- รายงาน **รายวัน / รายเดือน / รายปี**
- Report การซื้อรถ (รับซื้อเข้า) และ Report การขายรถ
- Report ลูกค้าค้างชำระ และประวัติการทวงหนี้ (Aging Report)
- Report อะไหล่เข้า-ออก และสต็อกอะไหล่ (รวม alert สต็อกต่ำ)
- Report รายได้แยกตามประเภท
- Report ค่าแรงช่าง
- Report กำไร-ขาดทุนอย่างง่าย (Simple P&L): รายได้รวม - ต้นทุนอะไหล่ - ค่าแรง - ค่าใช้จ่าย
- Report ภ.พ.30 (สรุป VAT รายเดือนสำหรับยื่นกรมสรรพากร)
- Report ภาษีเงินได้หัก ณ ที่จ่าย (สำหรับยื่น ภ.ง.ด.1 รายเดือน)
- Report เล่มทะเบียนที่อยู่ในความดูแล และรถที่ พ.ร.บ./ภาษีใกล้หมดอายุ
- Report กองกลางประกันรถหาย
- Report ผลการติดตามหนี้แยกตาม Collector

## 9. ระบบผู้ใช้งานและสิทธิ์ (User Access Management)

- **Role-Based Access Control (RBAC)**
- แต่ละ role สามารถ **กำหนดสิทธิ์การเข้าถึงฟังก์ชันต่างๆ ผ่าน UAM** ได้อย่างยืดหยุ่น

| Role | หน้าที่หลัก | Platform หลัก |
|---|---|---|
| **เจ้าของร้าน (Owner/Admin)** | ดูรายงาน, จัดการทุกอย่าง, กำหนดสิทธิ์, ดู audit trail | Mobile App |
| **เสมียน (Clerk)** | ลงข้อมูลการเงิน, สัญญา, ลูกค้า, บัญชีประจำวัน, มอบหมายงานติดตามหนี้ | Web App (PC) |
| **ช่าง (Technician)** | ลงข้อมูลงานซ่อม, เบิกอะไหล่ | Web App (PC) + Barcode Scanner |
| **พนง.ติดตามหนี้ (Collector)** | ออกพื้นที่ติดตามหนี้, เก็บเงินหน้างาน, บันทึกผลการติดตาม | Mobile App (Offline-first) |

- สามารถเพิ่ม role อื่นๆ ได้ตามต้องการ

- **ใบหักภาษี ณ ที่จ่าย (50 ทวิ)** — ตาม **ประมวลรัษฎากร มาตรา 50 ทวิ**
- ใบเสร็จชั่วคราวสำหรับ Collector (Field Receipt — PDF บนมือถือ)

## 11. Thai Tax Compliance (ภาษีและกรมสรรพากร)

### 11.1 VAT และใบกำกับภาษี
> **กฎหมาย:** ประมวลรัษฎากร มาตรา 80 (อัตรา VAT), มาตรา 86/4 (ใบกำกับภาษี)
> **พระราชกฤษฎีกา ฉบับที่ 799 พ.ศ. 2568** ขยายอัตรา VAT 7% ถึง **30 กันยายน 2569**

- คำนวณ **VAT 7%** ทุกรายการที่เกี่ยวข้อง
- ออก **ใบกำกับภาษีเต็มรูปแบบ** และ **ใบกำกับภาษีอย่างย่อ** ตามมาตรฐาน กรมสรรพากร
- ข้อมูลที่ต้องแสดงในใบกำกับภาษี (มาตรา 86/4): เลขประจำตัวผู้เสียภาษี, ชื่อ-ที่อยู่ผู้ขายและผู้ซื้อ, เลขที่ใบกำกับ, วันที่, รายการสินค้า/บริการ, ราคาก่อน VAT, VAT 7%, ราคารวม
- รองรับ **e-Tax Invoice by Email** (เหมาะสำหรับกิจการรายได้ต่ำกว่า 30 ล้านบาท/ปี)
- สรุปข้อมูลสำหรับยื่น **ภ.พ.30** ภายในวันที่ **15 ของเดือนถัดไป** (ยื่นออนไลน์ผ่าน e-Filing ขยายเป็น **23 ของเดือนถัดไป**)

### 11.2 ภาษีเงินได้หัก ณ ที่จ่าย (Withholding Tax)
> **กฎหมาย:** ประมวลรัษฎากร **มาตรา 50** (การหัก ณ ที่จ่าย) และ **มาตรา 50 ทวิ** (หนังสือรับรองการหัก ณ ที่จ่าย)

- คำนวณ **ภาษีเงินได้บุคคลธรรมดาหัก ณ ที่จ่าย** เมื่อจ่ายค่าแรงช่าง (คำนวณตามขั้นบันไดอัตราภาษีบุคคลธรรมดา — รายได้ต่ำกว่า 150,000 บาท/ปี อาจไม่ต้องหัก)
- สรุปข้อมูลสำหรับยื่น **ภ.ง.ด.1** ทุกเดือน:
  - ยื่นแบบกระดาษ: **ภายใน 7 วัน** หลังสิ้นเดือน
  - ยื่นออนไลน์ (e-Filing): **ภายใน 15 วัน** หลังสิ้นเดือน
- ออก **ใบหักภาษี ณ ที่จ่าย (50 ทวิ)** ให้พนักงานทุกคนที่ถูกหัก

### 11.3 ประกันสังคม (Social Security)
> **กฎหมาย:** พ.ร.บ.ประกันสังคม พ.ศ. 2533 **มาตรา 33**

- คำนวณ **เงินสมทบประกันสังคม**: ลูกจ้าง **5%** + นายจ้าง **5%** ของค่าจ้าง
- ฐานค่าจ้างที่ใช้คำนวณ: ต่ำสุด **1,650 บาท/เดือน**, สูงสุด **15,000 บาท/เดือน** (สูงสุดหัก 750 บาท/เดือน/ฝ่าย)
  - *(จะปรับเป็นสูงสุด 17,500 บาท/เดือน ตั้งแต่ 1 มกราคม 2569)*
- สรุปยอดนำส่งประกันสังคมภายในวันที่ **15 ของเดือนถัดไป**

## 12. ระบบ Audit Trail (บันทึกการกระทำ)

- บันทึก log **ทุกการเปลี่ยนแปลงข้อมูลสำคัญ**: ใครทำ, ทำอะไร, เมื่อไหร่, ค่าก่อน/หลังการแก้ไข
- ครอบคลุมทุก transaction ทางการเงิน: การรับเงิน, แก้ไขสัญญา, ลบรายการ, เปลี่ยนราคา
- เจ้าของร้านสามารถดูประวัติการแก้ไขย้อนหลังได้
- ป้องกันการทุจริต และใช้สำหรับตรวจสอบภายใน
- ข้อมูลส่วนบุคคล (เลขบัตร, เบอร์โทร) ต้อง mask ใน Log ตาม **PDPA มาตรา 37**

## 13. ระบบแจ้งเตือนอัตโนมัติ (Automated Notifications)

- แจ้งเตือนลูกค้า **ก่อนถึงกำหนดชำระค่างวด** (เช่น 3 วันล่วงหน้า) ผ่าน LINE/SMS
- แจ้งเตือน **พ.ร.บ./ภาษีใกล้หมดอายุ** (ล่วงหน้า 30 วัน) สำหรับรถที่ร้านดูแลเล่มทะเบียน
- แจ้งเตือนลูกค้า **ซ่อมเสร็จ รถพร้อมรับ**
- แจ้งเตือน **สต็อกอะไหล่ต่ำกว่า minimum** ให้เสมียน/เจ้าของร้าน
- แจ้งเตือน Collector เมื่อได้รับงานใหม่หรือเมื่อลูกค้ามาจ่ายที่ร้านแล้ว

ช่องทาง notification: **LINE Notify** หรือ LINE Official Account สำหรับแจ้งเตือนลูกค้าและเจ้าของร้าน

## 14. ข้อกำหนดทางเทคนิค (Technical Requirements)

- **อุปกรณ์หลัก**: คอมพิวเตอร์ตั้งโต๊ะ (เสมียน/ช่าง), มือถือ (เจ้าของ/Collector)
- **ไม่ต้อง** รองรับ offline mode สำหรับ Web App (ยกเว้น Mobile App ของ Collector ที่ต้อง Offline-first)
- **สาขา**: ปัจจุบันสาขาเดียว แต่ **ออกแบบให้รองรับหลายสาขาได้** ในอนาคต
- รองรับ **เครื่องสแกนบาร์โค้ด** (USB barcode scanner)
- รองรับ **เครื่องพิมพ์** สำหรับเอกสารต่างๆ (Thermal Printer 80mm + PDF)
- ต้องมี **กลยุทธ์สำรองข้อมูล (Backup)**: backup อัตโนมัติรายวัน เก็บไว้อย่างน้อย 30 วัน แนะนำใช้ cloud storage
- File Storage สำหรับรูปลูกค้าและรูปงานซ่อม: ต้องเป็น private access พร้อม backup
