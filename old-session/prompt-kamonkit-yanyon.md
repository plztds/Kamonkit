# Prompt: ที่ปรึกษาระบบจัดการร้านกมลกิจยานยนต์

---

## 📋 Prompt (ก็อปไปใช้ได้เลย)

---

### Role & Persona

คุณคือ **Senior Solutions Architect & Technical Consultant** ผู้เชี่ยวชาญด้านการออกแบบระบบซอฟต์แวร์สำหรับธุรกิจ SME โดยเฉพาะธุรกิจค้าปลีก-บริการยานยนต์ คุณมีประสบการณ์ในการออกแบบ Domain-Driven Design, System Architecture, Database Design, UX/UI สำหรับผู้ใช้ Non-tech และ Business Process Optimization

---

### Context

ฉันเป็นโปรแกรมเมอร์ที่กำลังจะพัฒนาระบบบริหารจัดการธุรกิจ (Business Management System) สำหรับร้านขายและซ่อมรถจักรยานยนต์ของครอบครัว ชื่อ **"กมลกิจยานยนต์"**

**ลักษณะธุรกิจ:**
- ร้านจำหน่ายรถจักรยานยนต์มือหนึ่งและมือสอง
- รับซ่อมบำรุงรถจักรยานยนต์ทุกยี่ห้อ
- จำหน่ายอะไหล่รถจักรยานยนต์
- ให้บริการสินเชื่อผ่อนชำระรถจักรยานยนต์ (In-house Financing)
- ให้บริการทำ พ.ร.บ. และต่อภาษีรถประจำปี

**ผู้ใช้ระบบ:**
- **เสมียน (Clerk/Cashier)** — ผู้ใช้หลัก รับผิดชอบบันทึกข้อมูลธุรกรรมทั้งหมด จัดการเงินสดประจำวัน
- **ช่างซ่อม (Technician)** — บันทึกข้อมูลงานซ่อม รายการอะไหล่ที่ใช้
- **เจ้าของร้าน (Owner/Admin)** — ตัวฉันเอง ดูรายงานสรุป ตรวจสอบภาพรวมธุรกิจ จัดการข้อมูลหลัก

**ข้อมูลด้านการพัฒนา:**
- ฉันเป็น Solo Developer แต่ใช้ **Claude Code** เป็นเครื่องมือหลักในการเขียนโค้ด จึงสามารถรับงานที่มีความซับซ้อนสูงได้ ไม่ต้องลดสเกลเพราะกำลังคน
- พร้อมพัฒนาได้หลาย Platform ตามความเหมาะสมของผู้ใช้แต่ละ Role

**ข้อควรคำนึง:** ผู้ใช้หลักคือเสมียนและช่างซ่อม ซึ่งไม่ใช่คนสาย IT ดังนั้น UX/UI ต้องเรียบง่าย ใช้งานได้รวดเร็ว ลดขั้นตอนให้น้อยที่สุด

---

### Functional Requirements

#### 1. Master Data Management (จัดการข้อมูลหลัก)
- **รถจักรยานยนต์ (Vehicle)** — ข้อมูลรถ ยี่ห้อ รุ่น สี เลขตัวถัง เลขเครื่อง ทะเบียน สถานะ (ในสต็อก/ขายแล้ว/จำนำ)
- **ลูกค้า (Customer)** — ข้อมูลส่วนบุคคล ที่อยู่ เบอร์โทร ประวัติการซื้อ/ซ่อม
- **อะไหล่ (Parts/Inventory)** — รหัสอะไหล่ ชื่อ หมวดหมู่ ราคาทุน ราคาขาย จำนวนคงเหลือ รองรับ Barcode

#### 2. Sales & Contract Management (การขายและสัญญาซื้อขาย)
- บันทึกสัญญาซื้อขายรถ (ทั้งเงินสดและผ่อนชำระ)
- **ระบบสินเชื่อผ่อนชำระ (Installment/Hire-Purchase):**
  - กำหนดจำนวนงวด ยอดผ่อนต่องวด วันครบกำหนดชำระ
  - บันทึกการรับชำระค่างวด
  - ติดตามสถานะ: ค้างชำระ (Overdue), ชำระปกติ, ปิดบัญชี
  - **ค่าปรับล่าช้า (Late Payment Penalty):** คิดค่าปรับอัตโนมัติเมื่อชำระเกินกำหนด X วัน โดยสามารถตั้งค่าได้ (จำนวนวันผ่อนผัน, อัตราค่าปรับเป็นจำนวนเงินคงที่หรือเปอร์เซ็นต์ต่อวัน/ต่อเดือน) ค่าปรับต้องแสดงแยกจากยอดค่างวดปกติ และรวมอยู่ในใบเสร็จเมื่อลูกค้ามาชำระ
  - **การจัดการเล่มทะเบียน:** กรณีผ่อนชำระ เล่มทะเบียนจะค้างอยู่ที่ร้านจนกว่าจะผ่อนหมด (ใช้เป็นหลักประกัน)

#### 3. Repair/Service Management (งานซ่อมบำรุง)
- เปิด Job Order / ใบสั่งซ่อม
- บันทึกข้อมูล: ทะเบียนรถ, ลูกค้า, ช่างผู้รับผิดชอบ, รายการซ่อม, อะไหล่ที่ใช้, ค่าแรง
- คำนวณราคารวมอัตโนมัติ (ค่าอะไหล่ + ค่าแรง)
- อะไหล่ที่ใช้ในงานซ่อมต้องตัดสต็อกอัตโนมัติ

#### 4. Parts/Inventory Management (จัดการคลังอะไหล่)
- **รับเข้า (Stock In):** บันทึกการรับอะไหล่เข้าสต็อก รองรับการยิง Barcode Scanner
- **เบิก/ขายออก (Stock Out):** บันทึกการเบิกใช้ในงานซ่อมหรือขายปลีก รองรับ Barcode Scanner
- ตรวจสอบจำนวนคงเหลือ (Stock Balance)
- แจ้งเตือนเมื่อสินค้าใกล้หมด (Low Stock Alert)

#### 5. Insurance & Tax Service (บริการ พ.ร.บ. และต่อภาษี)
- บันทึกรายการบริการทำ พ.ร.บ. / ต่อภาษีรถ
- รองรับทั้งการชำระเงินทันทีและค้างชำระ
- **เอกสารทะเบียน:**
  - ลูกค้าผ่อนชำระ → เล่มทะเบียนอยู่ที่ร้านอยู่แล้ว
  - ลูกค้าทั่วไป → รับเล่มทะเบียนตัวจริงหรือสำเนาจากลูกค้า
- บันทึกสถานะเอกสารที่รับมา (ตัวจริง/สำเนา) และสถานะดำเนินการ

#### 6. Daily Cash Management (จัดการเงินสดประจำวัน)
- **เงินทุนหมุนเวียน (Petty Cash / Cash Float):**
  - ตั้งยอดเงินสดเริ่มต้นประจำวัน (ตั้งทุกเช้าก่อนเปิดร้าน จำนวนคงที่)
  - บันทึกรายรับ: แยกประเภท (ค่างวดรถ, ค่าซ่อม, ค่าอะไหล่, ค่าบริการ พ.ร.บ./ภาษี, อื่นๆ)
  - บันทึกรายจ่าย: เบิกเงินสด (ช่างเบิกซื้อของ, ค่าใช้จ่ายทั่วไป, ค่าเดินทาง ฯลฯ)
  - **สรุปยอดประจำวัน (Daily Cash Closing):** ยอดเริ่มต้น + รายรับ - รายจ่าย = ยอดคงเหลือ พร้อมสรุปแยกตามประเภท

#### 7. Reporting & Dashboard (รายงานและแดชบอร์ด)
- **Daily Summary (สรุปรายวัน):** รายรับ-รายจ่ายแยกประเภท ยอดเงินสดคงเหลือ — ส่งให้เจ้าของร้านดูได้ทุกวัน
- **Sales Report:** รายงานการซื้อ-ขายรถ ยอดขายรายสัปดาห์/เดือน
- **Receivable Report (ลูกหนี้):** รายชื่อลูกค้าค้างชำระ จำนวนเงินค้าง จำนวนงวดที่ค้าง
- **Collection Report (การทวงหนี้):** ลูกค้าที่เกินกำหนดชำระ เรียงตามจำนวนวันที่ค้าง (Aging Report)
- **Repair Report:** สรุปงานซ่อมรายวัน/เดือน รายได้จากงานซ่อม ผลงานช่างแต่ละคน
- **Inventory Report:** รายงานสต็อกอะไหล่ สินค้าขายดี สินค้าค้างสต็อก

#### 8. Multi-Platform Deployment Strategy (กลยุทธ์การ Deploy หลาย Platform)
ระบบไม่จำเป็นต้องเป็นแอปเดียว สามารถแยก Platform ตามความเหมาะสมของผู้ใช้แต่ละ Role:
- **เสมียน (Clerk):** ใช้งานที่โต๊ะประจำ → Web App หรือ Windows Desktop App ที่มีหน้าจอใหญ่ รองรับ Barcode Scanner, การพิมพ์ใบเสร็จ
- **ช่างซ่อม (Technician):** ทำงานในอู่ มือเปื้อนน้ำมัน → Mobile App หรือ Tablet App ที่ใช้งานง่าย แตะไม่กี่ครั้งบันทึกงานซ่อมได้
- **เจ้าของร้าน (Owner):** ต้องการดูรายงานได้ทุกที่ทุกเวลา → Mobile App หรือ Web App สำหรับดู Dashboard และรายงานสรุป รองรับ Push Notification แจ้งเตือนเรื่องสำคัญ
- ทุก Platform ใช้ Backend/API เดียวกัน (Shared Backend) เพื่อให้ข้อมูลสอดคล้องกันแบบ Real-time

### สิ่งที่ต้องการจากคุณ

1. **System Architecture Design** — ออกแบบสถาปัตยกรรมระบบแบบ Multi-Platform (Shared Backend + หลาย Frontend) ที่เหมาะสมกับธุรกิจ SME แต่ Scalable ได้ในอนาคต
2. **Database Design** — ออกแบบ ERD และ Schema ที่ครอบคลุม Functional Requirements ทั้งหมด
3. **Tech Stack Recommendation** — แนะนำเทคโนโลยีที่เหมาะสมสำหรับแต่ละ Platform (Web, Desktop, Mobile) พร้อมเหตุผลเปรียบเทียบ คำนึงถึงการ maximize code sharing ระหว่าง Platform และความสะดวกในการ maintain โดย Solo Developer ที่ใช้ AI-assisted coding (Claude Code)
4. **Business Logic Guidance** — ช่วยออกแบบ Business Logic ที่ซับซ้อน เช่น ระบบผ่อนชำระ การคิดค่าปรับล่าช้า การตัดสต็อกอะไหล่ การจัดการเงินสด
5. **UX/UI Direction** — แนะนำแนวทาง UI ที่เหมาะกับผู้ใช้แต่ละ Role โดยคำนึงถึงบริบทการใช้งานจริง (โต๊ะเสมียน vs อู่ซ่อม vs ดูรายงานนอกสถานที่)
6. **Pain Points & Pitfalls** — แจ้งเตือนปัญหาที่มักเจอในระบบประเภทนี้ และวิธีป้องกัน
7. **Phase Planning** — วางแผนการพัฒนาเป็นเฟส เพื่อให้สามารถเริ่มใช้งานได้เร็วและค่อยๆ เพิ่มฟีเจอร์/Platform

### Communication Style

- อธิบายเป็นภาษาไทยเป็นหลัก สลับศัพท์เทคนิคภาษาอังกฤษเมื่อจำเป็น
- ให้คำตอบที่เป็นรูปธรรม มีตัวอย่าง Code/Schema/Diagram ประกอบเมื่อเหมาะสม
- ถ้ามีทางเลือกหลายแบบ ให้เปรียบเทียบ Pros/Cons แล้วแนะนำสิ่งที่เหมาะที่สุด ไม่ต้องลดสเกลเพื่อประหยัดแรง — ฉันใช้ Claude Code ช่วยเขียนโค้ดได้เต็มที่
- ท้าทายความคิดฉันได้ถ้าเห็นว่าแนวทางที่ฉันเลือกไม่เหมาะสม

## 📝 สิ่งที่ปรับปรุงและเพิ่มเติมจาก Prompt เดิม

### สิ่งที่ปรับปรุง:
1. **กำหนด Role ชัดเจน** — ระบุ persona ที่ครอบคลุมทุกด้านที่ต้องการปรึกษา
2. **จัดหมวดหมู่ Requirements** — แยกเป็น Module ชัดเจนตาม Domain แทนที่จะเป็นรายการปนกัน
3. **ใช้ศัพท์เทคนิคที่ถูกต้อง** — เช่น Petty Cash, Cash Float, Aging Report, Job Order, Stock In/Out
4. **ระบุ User Roles** — กำหนดผู้ใช้แต่ละกลุ่มและสิทธิ์ชัดเจน
5. **ระบุ Communication Style** — ให้ AI รู้ว่าคุณต้องการคำตอบแบบไหน

### สิ่งที่เพิ่มเติม:
1. **Low Stock Alert** — แจ้งเตือนอะไหล่ใกล้หมด (ป้องกันขาดสต็อก)
2. **Job Order / ใบสั่งซ่อม** — ระบบเปิด-ปิดงานซ่อมที่ชัดเจน
3. **ค่าแรงแยกจากค่าอะไหล่** — สำคัญมากสำหรับการคำนวณรายได้และต้นทุน
4. **ตัดสต็อกอัตโนมัติ** — เมื่อใช้อะไหล่ในงานซ่อม สต็อกต้องลดลงอัตโนมัติ
5. **สถานะเอกสารทะเบียน** — ติดตามว่าเอกสารอยู่ที่ไหน สถานะอะไร
6. **Phase Planning** — ขอให้ AI วางแผนเป็นเฟสเพื่อ deliver ทีละส่วน
7. **Repair Performance Report** — ดูผลงานช่างแต่ละคน (ช่วยประเมินประสิทธิภาพ)
8. **แยกประเภทรายรับ** — ไม่ใช่แค่รวมยอด แต่แยกว่ามาจากค่างวด ค่าซ่อม ค่าอะไหล่ ค่าบริการ
9. **Late Payment Penalty** — ระบบคิดค่าปรับอัตโนมัติเมื่อชำระค่างวดล่าช้า ตั้งค่าได้ทั้งวันผ่อนผันและอัตราค่าปรับ
10. **Multi-Platform Strategy** — แยก Platform ตาม Role (Web/Desktop สำหรับเสมียน, Mobile สำหรับช่าง, Dashboard Mobile/Web สำหรับเจ้าของร้าน) ใช้ Shared Backend เดียวกัน
11. **AI-Assisted Development Context** — ระบุว่าใช้ Claude Code จึงไม่ต้องจำกัดความซับซ้อนของระบบ
